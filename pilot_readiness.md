# SignalForge Pilot Readiness Checklist
**Phase 6V — Real-World Pilot Readiness**

Use this checklist before onboarding a live pilot client. Each area must be verified  
and signed off. A `GET /system/pilot-readiness` score ≥ 80 is the automated gate;  
this document covers the human-verified operational checks.

---

## Infrastructure

- [ ] MongoDB Atlas cluster (or self-hosted) reachable from Docker network  
- [ ] Redis reachable — `redis-cli ping` returns `PONG`  
- [ ] All required collections exist and are indexed (`GET /system/indexes`)  
- [ ] Docker Compose services stable for ≥ 10 minutes (`docker compose ps`)  
- [ ] Persistent volumes mapped correctly (Mongo data directory not ephemeral)  
- [ ] Resource limits set in `docker-compose.prod.yml` (CPU + memory)  

---

## Security

- [ ] `SIGNALFORGE_AUTH_ENABLED=true` in production environment  
- [ ] `JWT_SECRET` is a random 32-byte hex string (not the dev default)  
- [ ] API key(s) provisioned for pilot client in the secrets store  
- [ ] `SIGNALFORGE_RATE_LIMIT_ENABLED=true` active  
- [ ] `CORS_ORIGINS` restricted to the pilot client's domain (not `*`)  
- [ ] `.env.production` is NOT committed to git (confirm with `git status`)  
- [ ] `POST /auth/token` tested: valid key → 200, invalid key → 401  
- [ ] Unauthenticated `GET /system/pilot-readiness` returns 401  

---

## Recovery & Resilience

- [ ] `GET /system/recovery-status` returns `orphaned_task_risk: false`  
- [ ] `GET /system/recovery-status` shows 0 stuck orchestrations  
- [ ] Worker heartbeat endpoint tested: `POST /workers/heartbeat` → 200  
- [ ] Worker recovery tested: `POST /workers/recover-orphaned` → 200  
- [ ] Pre-deployment backup created and dry-run restore verified:  
  ```
  python scripts/backup_restore.py backup --out pre_pilot_backup.json
  python scripts/backup_restore.py restore --file pre_pilot_backup.json --dry-run
  ```  
- [ ] Rollback procedure tested in staging (see `docs/DEPLOYMENT_RUNBOOK.md §8`)  

---

## Observability

- [ ] `GET /system/telemetry` returns request counts and error rates  
- [ ] `GET /system/audit-log` returns entries for recent system events  
- [ ] Tracing middleware active — all requests appear in `/system/telemetry`  
- [ ] Error rate < 1% on staging smoke test  
- [ ] `GET /health/detailed` passes (all sub-checks green)  

---

## Autonomy & Workflow

- [ ] At least one orchestration successfully processed end-to-end in staging  
- [ ] Approval queue functional: `GET /approvals/pending` returns correct results  
- [ ] Agent task queue processing: `GET /workers/queue-depth` shows movement  
- [ ] Client memory read/write verified: `POST /client-memory/{slug}` → 200  
- [ ] Recommendation status lifecycle tested (pending → accepted / rejected)  

---

## Load & Stability

- [ ] 50-request burst smoke test completed with < 1% error rate  
- [ ] No memory leaks detected over 5-minute sustained test  
- [ ] Worker registry does not accumulate stale workers during test  
- [ ] Rate limiter returns 429 correctly when burst limit is exceeded  

---

## Go / No-Go Gate

| Check | Pass Threshold |
|-------|---------------|
| `GET /system/pilot-readiness` score | ≥ 80 |
| `GET /system/pilot-readiness` `ready` | `true` |
| All Infrastructure checks above | ✅ |
| All Security checks above | ✅ |
| All Recovery checks above | ✅ |
| Error rate on staging smoke | < 1% |

**All gates must pass before scheduling the live pilot kick-off call.**
